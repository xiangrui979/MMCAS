# 对抗自检与证伪（建模手）

好模型不是"看起来对"，是"打不倒"。定案前用本 skill 攻击自己的方案；攻击不垮，才写入任务卡定稿。

## 定案前四问（每个模型路线必答，答不出即不通过）

1. **假设问**：每条假设有数据或题目依据吗？如果去掉这条假设，模型还能解吗？哪条假设是结论成立的前提——这条必须做灵敏度分析。
2. **简化问**：有没有更简单的模型能达到同等效果？现在这个复杂度换来了什么可验证的收益？答不出收益 = 过度设计，退回简单方案。
3. **数据问**：数据量撑得起这个模型的参数吗？有没有数据泄漏（用了答案期的信息）？缺失/异常数据怎么处理的，处理方式会不会扭曲结论？
4. **失败问**：这个模型在什么输入下会给出荒谬结果？边界情况（0 值、极端值、空数据）行为合理吗？

## 模型特定证伪清单

读 `references/falsification-checklist.md` 按模型类型执行：
- 优化：可行性残差、基线对比、多起点重跑、最优间隙、约束边界处的行为
- 仿真/微分方程：单位与守恒量、初边值条件、步长/网格收敛、已知极限情形复现
- 预测：时间顺序切分（禁止未来泄漏）、朴素基线对比、残差分析、外推风险
- 回归/分类：切分完整性、类别不平衡、多重共线性、校准、外推
- 评价/排序：指标方向与归一化、权重理由、权重灵敏度、排名稳定性
- 网络/空间/聚类：图与距离构造、分辨率、参数与种子稳定性

## 结果异常时的 5-Why 根因

求解结果异常（不合理数值、与直觉冲突、无法复现）时，连续追问 5 层"为什么"，追到根因再动手，禁止表层修补：
1. 结果错了？（数值错误 vs 模型错误 vs 数据错误，先定位层）
2. 数值错：算法实现、收敛条件、浮点精度？
3. 模型错：假设不成立、目标函数与题意不符、约束遗漏？
4. 数据错：单位、清洗、缺失处理、泄漏？
5. 根因确认后，修复 + 回归验证，并把根因与修复写入任务卡注释。

## 关键数字的独立复核（定稿前）

- 所有将写进论文结论的数字：从原始数据到最终数字的链路能完整回溯（数据文件→脚本→中间结果→结论），链路断裂的数字不得进入论文。
- 有 subagent 可用时，派独立 subagent 只拿冻结的模型方案+数据做盲审（不读起草过程），交叉验证结论；不可用时降级为自审并标注置信度。

## 与任务卡的关系

自检通过 = 任务卡 modeling 段定稿 + 在卡上标注"已通过对抗自检"。未通过的问题写进卡注释作为派发编程手的验收标准（例如"必须报告最优间隙""必须做灵敏度分析"）。
