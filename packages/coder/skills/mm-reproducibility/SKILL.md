# 复现性工程（编程手）

论文里的每个数字，评审人都应当能从数据+代码重新算出来。这是国赛/美赛高奖论文与普通论文的分水岭。

## 三要素（每次运行必记录）

1. **种子**：所有随机性（数据切分、初始化、抽样、仿真）显式设置并记录。
2. **环境**：Python 版本、关键包版本（numpy/scipy/sklearn/pandas 等）。环境变化（装新包/升级）必须写 `workspace/environment/` 环境日志并广播——已有流程，勿绕过。
3. **数据版本**：输入数据的来源与哈希（`sha256sum` 前 8 位足够），数据更新时哈希变化，下游结果全部重跑。

## 结果回溯链

每个交付到任务卡的关键数字，链路必须完整：

```
数据文件(哈希) → 脚本路径 → 运行参数/种子 → 中间结果 → 最终数字
```

- 链路任何一环缺失，该数字不得交付给论文手（宁可重跑也不要不可追溯的数字）。
- 脚本必须能一键从头跑到尾（入口脚本 + 参数），不接受"手动跑了几步"。
- 输出中间结果落盘（npz/csv），下游脚本只消费中间结果，不重复长计算。

## 运行日志规范

- 每次正式运行：脚本名、参数、种子、耗时、收敛状态（或终止原因）追加写入任务卡 run log 区。
- 结果被采纳的那次运行必须完整记录；参数调优的中间尝试可简记（参数+结果一行）。

## 环境变更纪律（已有规则强化）

- 装新包/改版本 → 环境日志 + 广播 → 相关任务卡标注"环境已变，结果待重验"。
- 队友端环境不同步时走既定的环境同步协议（方案 B：lockfile + P2P wheelhouse），不自行散装安装。

## 数字变更纪律（已有规则强化）

已写入任务卡的数字，任何变更必须写明原因并记录在卡上——论文手引用的数字以卡上最新记录为准，变更不通知 = 事故。
