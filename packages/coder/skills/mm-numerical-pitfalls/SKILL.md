# 数值计算常见坑（编程手）

结果异常时的第一排查工具：按本清单逐项过，90% 的"模型错了"其实是"坑踩了"。

## 浮点与数值

- 大数+小数：数量级差 >10^8 时小数被吞。用 log 空间、Kahan 求和或变换量纲。
- 条件数：矩阵求逆/求解前 `np.linalg.cond`；条件数 >10^12 用 SVD/伪逆/正则化，并报告条件数。
- 归一化缺失：特征量纲差异大时未归一化，导致梯度类算法收敛慢/距离度量被主导。
- 溢出/下溢：softmax、exp 组合用 log-sum-exp；概率连乘用对数。
- 整数除法/类型：Python 里 `1/2` 与 `1//2`、int 溢出为 object 类型（大数运算变慢）、DataFrame 类型混用。

## 优化陷阱

- 未收敛就当答案：检查收敛标志与最优间隙（IP 求解器）、梯度范数（连续优化），报告"终止原因"而非只看数值。
- 局部最优误报全局：多起点重跑（不同初值/种子）对比；NP-hard 问题声明"近似解"而非"最优解"。
- 不可行性被忽视：求解器返回 infeasible 时继续用残差较大的"解"——必须报告可行性残差。
- 罚函数调参：罚因子过大数值病态、过小约束不满足；可行域窄时考虑约束修复策略。
- 目标函数与题意不符：最大化写成了最小化、漏约束、权重方向写反——先做"小样例手工可算"验证。

## 统计陷阱

- 数据泄漏：用未来信息（如整段序列统计量）预处理训练段；切分在预处理之前做。
- 多重比较：几十个假设一起检验时，p<0.05 必有假阳性——Bonferroni/FDR 校正或预注册假设。
- 伪相关：两组都有趋势的序列直接算相关；非平稳序列先差分/协整检验。
- 小样本过拟合：样本 <100 用复杂模型，交叉验证时报告置信区间而非单点估计。
- 异常值未处理：均值被极端值绑架；先可视化分布，再决定处理方式并留痕。

## 时间序列陷阱

- 未来函数：移动平均/归一化用了未来窗口。
- 序列过短：<30 点参数估计不可靠，改用指数平滑等简单方法。
- 季节性混入趋势：不分解直接建模。

## 评估陷阱

- 指标方向：准确率 vs 损失、最大化 vs 最小化（AHP/熵权法里指标方向反了结论全反）。
- 指标不匹配问题：分类不平衡用 accuracy（全猜多数类也高）——用 F1/AUC。
- 归一化方法影响排名：TOPSIS/熵权法里归一化方式（min-max/向量/极差）改变结果——报告方法并做稳定性对比。

## 排查流程

结果可疑时：先定位层（数据？算法？模型？）→ 小样例手工验证（能否手算）→ 对照本清单 → 修复 + 回归验证 → 根因写入任务卡注释。修不动时在任务卡标注 blocking 并请求建模手介入，不静默改模型。
