# 代码实现纪律（MMCAS 编程手）

代码的唯一使命：忠实、可验证地实现建模手任务卡上的模型。实现偏离模型 = 废品。

## 开工前

1. 通读任务卡 modeling 段：模型定义、符号体系（`workspace/analysis/notation.md`）、输入数据、期望输出、验收标准。
2. 变量命名与建模手符号体系一一对应（如符号 α 就写 `alpha`，不要自行改名）；关键公式在代码注释里复述原公式。
3. 有题型示范需求时查 `references/playbooks/`（11 个题型完整解题示范，算法选型参考）。
4. 有疑问（模型定义歧义、数据缺失）→ 任务卡注释提问，不自行拍板改模型。

## 编码纪律

- **验证先行**：先写最小可运行单元（一个函数+一个断言），跑通再扩展；禁止一口气写完几百行再调试。
- **数值稳定性**：避免大数小数直接相加；用稳定算法（如 log-sum-exp、SVD 代替正规方程）；矩阵求逆前检查条件数；优化器收敛参数显式设置（迭代上限、容忍度）。
- **量纲与边界**：输入数据先做 sanity 检查（单位、数量级、缺失值、异常值）；输出结果先做合理性检查（符号对不对、数量级对不对、边界输入下行为是否合理）再写进任务卡。
- **随机性受控**：一切含随机的代码显式设 `random_state`/seed，写入运行日志。
- **可读性**：函数短小、命名诚实、关键步骤注释"为什么"而非"是什么"。

## 交付规范

结果写入 `workspace/code/`（代码）与 `workspace/figures/`（图），任务卡 result 段写：
- 运行环境（Python 版本、关键包版本）、随机种子、数据文件版本
- 关键数值结果（论文手将引用的数字必须精确到有效位，附计算脚本路径）
- 图表文件路径与图表要论证的结论（一句话，见 figure-contract 规则：先定论证逻辑再画图）

## 图规范（论文手引用前必看）

每张图交付前回答：这张图要证明什么结论？每个子图贡献了什么独立证据？黑白打印下结论仍可读吗？无独立证据的子图删除。发表级样式要点见 `references/figure-style-guide.md`。
